# R2024b preflight corrections — current implementation

The preflight uses the same two-column DOUBLE [time,value] From Workspace
input format as pam3_assign_inputs.m in the earlier PAM3 package that the
user successfully executed in MATLAB R2024b. It does not use the rejected
structure with a missing time field.

Input is constructed in quality_fixture_input.m: time = (0:N-1)'*Ts.
The exact same Ts configures the solver, source block, S-function and sinks.
The configuration, input and sample time exist in the MODEL workspace before
dependent blocks are created. Interpolation stays off, and the final-value
mode explicitly holds the final value. These settings preserve discrete input.

The actual error input and controller output are both logged. The validator
checks sample count, finite scalar data, and timestamps on the scheduled
clock before comparing every original value by index. It uses no value
tolerance, signal shifting, or search for delay. Native errors, including
simulation errors, save diagnostics to validation/native_preflight_failure.mat.

A known defect in the old validator was reproduced independently: comparing
clock values formed by k/fs to k*(1/fs) using strict previous-value ZOH
selected the previous sample at some boundaries. Fixture 7 produces 31 false
mismatches even when supplied perfect output data. The corrected indexing
produces zero; genuine value errors, missing samples and a real clock shift
remain detectable. This explains a verified validator defect, not proof that
all native failures necessarily had that cause.

Checks actually completed in Octave 8.4.0:

- Clock-alignment regression described above.
- All eight native-preflight fixture input arrays: finite double N-by-2,
  unmodified sample values and exact integer-multiple timestamps.
- The REAL quality_controller_sfun.m Outputs/Update callbacks invoked with a
  TEST DOUBLE block object: 8 independent fixtures, 20,928 samples, all outputs
  match the golden data. Repeated Outputs calls do not mutate state; Update
  advances the state; declared sample times and state sizes agree.
- Static MATLAB syntax lint.

The callback test double is NOT Simulink. It cannot validate solver scheduling,
native block parameter interpretation, power-system model compilation or plot
rendering. MATLAB/Simulink is not installed in this environment. The actual
preflight and four converter simulations still require execution in MATLAB.
No native success or converter performance has been prefilled in this ZIP.

Install the complete current ZIP into a NEW folder to avoid mixing revisions.
The startup banner identifies this as the R2024b input-array revision.
